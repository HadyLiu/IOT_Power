# 构建发布流程

> 本项目不使用 GitHub Actions，统一在本机（Ubuntu）用 cargo 与 Docker 打包，再用 `gh` 上传 Release。架构见 [架构设计.md](架构设计.md)。

## 1. 开发环境
```bash
# Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup target add x86_64-pc-windows-gnu
# Ubuntu 依赖（rusb 需要 libusb；nusb 不需要但保留以便切换）
sudo apt install -y build-essential pkg-config libusb-1.0-0-dev libudev-dev \
  libxkbcommon-dev libgl1-mesa-dev libwayland-dev
```

## 2. 本地构建
```bash
cargo fmt --check && cargo clippy --all-targets -- -D warnings
cargo test --workspace            # 含协议 CRC 示例帧与 poll_*.bin 样本解析
cargo run -p iot-power            # 调试运行
cargo build --release -p iot-power
```
产物：`target/release/iot-power`（Linux）、`target/x86_64-pc-windows-gnu/release/iot-power.exe`（Windows）。

### 2.1 Windows USB 访问
- 设备需绑定 **WinUSB** 驱动（官方 IoT Power 软件安装后通常已是 WinUSB，设备管理器显示 “DC3005U WinUSB”）。若不是，可用 Zadig 选择 VID 0408 / PID 1043 安装 WinUSB（是否影响官方软件见 [PRD §8](PRD.md#8-待确认) #11）。
- 访问库：`nusb`（纯 Rust，直接走 WinUSB，无需额外 DLL，首选）；备选 `rusb`（需静态链接 libusb，`features = ["vendored"]`）。
- 同一时刻只能一个进程 claim 接口，测试前关闭官方软件。

## 3. Linux udev 规则
`packaging/99-dc3005u.rules`：
```
SUBSYSTEM=="usb", ATTR{idVendor}=="0408", ATTR{idProduct}=="1043", TAG+="uaccess"
```
安装：
```bash
sudo cp packaging/99-dc3005u.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
# 重新插拔设备
```
（`uaccess` 只授权当前登录用户；无桌面会话的场景（如 SSH、CI）可改用 `MODE="0660", GROUP="plugdev"`，不建议用 `MODE="0666"`，那样本机任何用户都能控制电源。）.deb 安装时自动放置该规则。

## 4. 版本号规则
- 语义化版本 `MAJOR.MINOR.PATCH`；1.0 之前：MINOR = 里程碑（0.1 文档、0.2 = M1、0.3 = M2 …，0.6 = M5），PATCH = 修复。
- 唯一来源：workspace `Cargo.toml` 的 `version`；程序标题与“关于”读 `env!("CARGO_PKG_VERSION")`。
- Git 标签 `vX.Y.Z`；每次发布先更新 [CHANGELOG.md](CHANGELOG.md)，把 `[Unreleased]` 内容移到新版本下。

## 5. 打包
### 5.1 Linux .deb
```bash
cargo install cargo-deb
cargo deb -p iot-power
# 产物 target/debian/iot-power_X.Y.Z-1_amd64.deb
```
`app/Cargo.toml` 的 `[package.metadata.deb]` 需包含：二进制 → `/usr/bin/`，`.desktop` 与图标，`99-dc3005u.rules` → `/lib/udev/rules.d/`，`postinst` 中执行 `udevadm control --reload-rules && udevadm trigger`，许可证文件（含字体 OFL）。

### 5.2 用 Docker 编译 Linux 与 Windows
编译镜像 `rust-cross-builder:latest`（`packaging/docker/Dockerfile`）基于本机已有的 `cross-systemconnect-packager:latest`（Debian bookworm + Rust 1.98.1 + mingw-w64 + GTK/WebKit），补装 libudev/libusb、Mesa GL、NSIS、clippy/rustfmt、cargo-deb，并设好 `x86_64-pc-windows-gnu` 的链接器环境变量。同一个镜像也用于编译 Cross-SystemConnect。源码运行时挂载到 `/src`，cargo 缓存和 `target` 放在 Docker 卷里（`iot-power-cargo-registry`、`iot-power-cargo-git`、`iot-power-target`），不占用本机 `target/`。
```bash
bash scripts/docker-build.sh               # IOT_Power：Linux + Windows → dist/
bash scripts/docker-build.sh check         # fmt + clippy -D warnings + test + Windows 目标 check
bash scripts/docker-build.sh csc           # Cross-SystemConnect（默认 ../Cross-SystemConnect，可设 CSC_DIR）
bash scripts/docker-build.sh shell         # 进入容器
bash scripts/docker-build.sh --image       # 重建镜像后再编译
```
产物：`dist/linux/iot-power`、`dist/windows/iot-power.exe`、`dist/IOT_Power-X.Y.Z-linux-x86_64.tar.gz`、`dist/IOT_Power-X.Y.Z-windows-x64.zip`。NSIS 安装包（§5.3）在容器内用 `makensis -DVERSION=X.Y.Z packaging/nsis/installer.nsi` 生成。
图标与版本信息用 `winres`（build.rs，需 mingw 的 `windres`）；`#![windows_subsystem = "windows"]` 隐藏控制台。

### 5.3 Windows NSIS 安装包
`packaging/nsis/installer.nsi` 要点：安装到 `$PROGRAMFILES64\IOT_Power`，开始菜单与桌面快捷方式，卸载程序，附带 LICENSE 与 OFL。产物 `dist/IOT_Power-Setup-X.Y.Z.exe`。另提供便携 zip（单 exe）。驱动不随包安装（依赖 WinUSB；是否附 Zadig 说明见 [PRD §8](PRD.md#8-待确认) #11）。

## 6. 发布
```bash
git tag vX.Y.Z && git push origin vX.Y.Z
gh release create vX.Y.Z --title "vX.Y.Z" --notes-file <(sed -n '/## \[X.Y.Z\]/,/## \[/p' Doc/CHANGELOG.md)
gh release upload vX.Y.Z \
  dist/IOT_Power-Setup-X.Y.Z.exe dist/IOT_Power-X.Y.Z-windows-x64.zip \
  target/debian/iot-power_X.Y.Z-1_amd64.deb dist/SHA256SUMS
```
校验和：`sha256sum dist/* target/debian/*.deb > dist/SHA256SUMS`。

## 7. 发布检查清单
- [ ] `Cargo.toml` 版本号、CHANGELOG 已更新，日期正确
- [ ] `cargo fmt`、`clippy`、`cargo test` 全部通过
- [ ] [测试用例.md](测试用例.md) 中「首测里程碑」不晚于本次版本的用例全部通过（自动用例跑 `cargo test`，其余实机）；P2 用例只在包含对应功能的版本里执行
- [ ] 项目许可证已确定（[PRD §8](PRD.md#8-待确认) #12）
- [ ] Windows：NSIS 安装/卸载、TC-31 通过；exe 无控制台窗口；图标正确
- [ ] Linux：.deb 安装后免 sudo 可连接（TC-32），卸载干净
- [ ] 中文字体显示正常（TC-30），英文界面完整
- [ ] 许可证文件（项目 + egui 等依赖 `cargo about` 报告 + 字体 OFL）已打包
- [ ] SHA256SUMS 生成，Release 说明与文档链接正确
