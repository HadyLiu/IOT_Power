## 1. 设备识别

| 项 | 值 |
| --- | --- |
| 产品名 | DC3005U WinUSB |
| 厂商字符串 | `DC3005U_Device` |
| idVendor | `0x0408` |
| idProduct | `0x1043` |
| bcdUSB | 2.00 |
| 电压设定范围 | **0.8 ~ 24 V** |
| 电流设定范围 | **0.5 ~ 5.0 A** |
| 配置 | 1 |
| 接口 | 0，Vendor Specific (`0xFF`) |
| 端点 OUT | `0x01`，Bulk，wMaxPacketSize=64 |
| 端点 IN | `0x82`，Bulk，wMaxPacketSize=64 |

主机侧建议使用 WinUSB / libusb。同一时刻只能有一个进程打开该接口；官方上位机打开时，其它程序无法 claim。

---

## 2. 链路与事务模型

1. 可选：发送连接命令 `0x01`，首次可能收到约 63 字节身份信息。
2. 循环：发送读数命令 `0x05`，每次读取一帧约 **10072** 字节应答。
3. 需要改设定时：发送 `0x03`（电流+电压打包）。
4. 需要开关输出时：发送 `0x06`（`01`/`00`）。

未观察到独立的「断开 USB」命令。进程退出并 release 接口，或拔线即可。试探命令 `0x00` 无应答。

推荐超时：写/读各 1–3 秒。读数间隔可按 UI 刷新需求选择（抓包中官方软件发送很频繁）。

## 3. 主机 → 设备帧格式

所有主机命令均为 Bulk OUT `0x01` 上一帧二进制：

```text
+------+------------------+------+------------------+
| 0x55 | 命令与参数…      | 0xAA | CRC32 小端 4 字节 |
+------+------------------+------+------------------+
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| SOF | 1 | 固定 `0x55` |
| Body | ≥2 | 命令字 + 参数（见第 4 节） |
| EOF | 1 | 固定 `0xAA` |
| CRC | 4 | CRC-32/IEEE（zlib），**覆盖范围 = SOF + Body + EOF（含 `0x55` 与 `0xAA`）**，小端存储 |

### 3.1 CRC 计算

```python
import struct, zlib

def build_frame(body_after_55: bytes) -> bytes:
    """body_after_55: 命令字及参数，不含 0x55 / 0xAA / CRC。"""
    payload = bytes([0x55]) + body_after_55 + bytes([0xAA])
    crc = zlib.crc32(payload) & 0xFFFFFFFF
    return payload + struct.pack("<I", crc)
```

校验示例：

| payload（至 AA） | CRC32 | 完整帧 |
| --- | --- | --- |
| `55 01 00 AA` | `0xEA56004D` | `55 01 00 AA 4D 00 56 EA` |
| `55 05 00 AA` | `0xED5FA891` | `55 05 00 AA 91 A8 5F ED` |

## 4. 命令一览

| 命令字 | Body（不含 55/AA/CRC） | 作用 | 典型 IN 应答 |
| --- | --- | --- | --- |
| `0x01` | `01 00` | 连接 / 握手 | ≈63 B 身份，或已连接时返回读数类数据 |
| `0x05` | `05 00` | 读数轮询 | ≈10072 B 测量帧 |
| `0x03` | `03 04` + 4 字节设定打包 | 同时设置电压、限流 | 短应答；随后读数中 @52/@54 回显 |
| `0x06` | `06 04` + `01/00 00 00 00` | 输出开 / 关 | 短应答 |
| `0x00` | `00 00`（试探） | 无效 | 无应答（超时） |

完整帧示例：

```text
连接: 55 01 00 AA 4D 00 56 EA
读数: 55 05 00 AA 91 A8 5F ED
设定: 55 03 04 C0 5D E8 03 AA C9 DD 30 B8   # 见 4.3
开:   55 06 04 01 00 00 00 AA A1 36 C6 8B
关:   55 06 04 00 00 00 00 AA 11 1F A6 B6
```

### 4.1 连接 `0x01`

```text
Body: 01 00
```

身份应答（约 63 字节，ASCII，零填充）布局观察：

| 区段 | 内容示例 |
| --- | --- |
| 开头 | `DC3005U` |
| 中部 | 序列号字符串，如 `8B63A8F401E4` |
| 其后 | 固件版本，如 `1.9.5` |

精确字段边界以实现为准；开发时可按 `\0` 分隔解析可见字符串。

### 4.2 读数 `0x05`

```text
Body: 05 00
```

应答见第 5 节。

### 4.3 设定电压与限流 `0x03`

```text
Body: 03 04 | voltage_u16 (mV) | current_u16 (mA，限流)
            \___________________________/
                 小端，共 4 字节
```

- `0x04`：后续数据长度 4。
- **低 16 位（帧中先出现的 2 字节）= 电压设定，单位 mV；高 16 位（后 2 字节）= 限流（输出电流上限），单位 mA**（用户 2026-10-10 确认）。设定分辨率 1 mV / 1 mA。
- 字节层面推导（抓包帧 `55 03 04 C0 5D E8 03 AA C9 DD 30 B8`）：参数 4 字节为 `C0 5D E8 03`，按小端 u32 读 = `0x03E85DC0`；按 `<HH` 读 = (`0x5DC0`, `0x03E8`) = (24000, 1000) → **24.000 V、1.000 A 限流**。
- v0.3 写的「低 16 位 = 电流」只是命名说反，字节排列与本结论不矛盾，帧本身不变。

```python
import struct, zlib

def frame_set_vi(voltage_mv: int, current_ma: int) -> bytes:
    body = bytes([0x03, 0x04]) + struct.pack("<HH", voltage_mv & 0xFFFF, current_ma & 0xFFFF)
    payload = bytes([0x55]) + body + bytes([0xAA])
    return payload + struct.pack("<I", zlib.crc32(payload) & 0xFFFFFFFF)

# 抓包示例 0x03E85DC0（字节 C0 5D E8 03）：
# voltage=0x5DC0 (24000 mV = 24 V), current=0x03E8 (1000 mA = 1 A 限流)
# frame_set_vi(24000, 1000)
```

#### 设定范围（产品规格）

| 量 | 最小 | 最大 |
| --- | --- | --- |
| 电压设定 | **0.8 V**（u16 800） | **24 V**（u16 24000） |
| 限流设定 | **0.5 A**（u16 500） | **5.0 A**（u16 5000） |

上位机下发 `0x03` 前必须保证值在范围内（IOT_Power 的做法：超界拒绝下发，IO 线程再兜底钳位）；设备收到超出范围的值会怎样未测。

**单位：** 设定电压 u16 以 mV 计（与实时电压 `u16@30/1000` 同单位）；限流 u16 以 mA 计（实时电流是另一种换算，见 5.2，二者不要混用）。读数帧偏移 52 回显电压设定（mV），偏移 54 回显限流（mA），即原样回显这 4 字节。

---

### 4.4 开关 `0x06`

```text
开: Body = 06 04 01 00 00 00
关: Body = 06 04 00 00 00 00
```

第 3 字节（`01`/`00`）为开关；其后三字节为 0。对应官方 UI 哪个按钮待确认；语义上是输出开关，不是断开 USB。

## 5. 设备 → 主机：读数帧（≈10072 字节）

Bulk IN `0x82`。头部多数字段为小端整数。

### 5.1 头部布局（已用于开发）

```text
偏移   类型    换算 / 含义
0..15  —       多为 0
16     u32     帧序号（单调递增）
20     u32     实时电流原始值 → mA = raw / 100000
24     u32     实时功率原始值 → W  = raw / 1e8
28..29 —       常见为 0
30     u16     实时电压原始值 → V  = raw / 1000
32..51 —       其它状态/统计（未完全标定）
52     u16     电压设定回显，mV（与命令 0x03 低 16 位一致）
54     u16     限流设定回显，mA（与命令 0x03 高 16 位一致）
56..   —       后续为采样/波形区（布局未解析）
```

### 5.2 实时量换算（已双工况验证）

| 物理量 | 公式 | 单位 |
| --- | --- | --- |
| 电压 V | `u16_le(data[30:32]) / 1000` | V |
| 电流 I | `u32_le(data[20:24]) / 100000` | mA |
| 功率 P | `u32_le(data[24:28]) / 1e8` | W |

校验关系：`P ≈ V × (I_mA / 1000)`，误差与采样抖动一致。

```python
import struct

def parse_measurement(data: bytes) -> dict:
    if len(data) < 56:
        raise ValueError("short frame")
    seq = struct.unpack_from("<I", data, 16)[0]
    i_raw = struct.unpack_from("<I", data, 20)[0]
    p_raw = struct.unpack_from("<I", data, 24)[0]
    v_raw = struct.unpack_from("<H", data, 30)[0]
    set_v, set_i = struct.unpack_from("<HH", data, 52)
    return {
        "seq": seq,
        "voltage_V": v_raw / 1000.0,
        "current_mA": i_raw / 100000.0,
        "power_W": p_raw / 1e8,
        "set_voltage_mV": set_v,
        "set_current_mA": set_i,
    }
```

### 5.3 标定摘要

| 工况 | UI 约值 | 解析结果 |
| --- | --- | --- |
| A | 4.999 V，≈575 mA | V=4.999，I≈575 mA，P≈2.874 W |
| B | 6.999 V，≈13.8 mA（8 组） | V=6.999，I≈13.84 mA，P≈0.097 W，P≈V×I |

## 6. 推荐主机状态机

```text
打开设备(VID=0408,PID=1043) → claim interface 0
        │
        ▼
   发送 0x01 连接 ──(可选解析身份)──┐
        │                         │
        ▼                         │
   ┌─ 循环 ─────────────────────┐ │
   │ 发送 0x05                  │ │
   │ 读 10072 字节              │◄┘
   │ 解析 V/I/P / 刷新 UI       │
   │ 若需改设定 → 发送 0x03     │
   │ 若需开关   → 发送 0x06     │
   └─────────────┬──────────────┘
                 ▼
        release / 关闭句柄
```

错误处理建议：

- `LIBUSB_ERROR_NOT_FOUND` / 找不到设备：检查线缆与驱动。
- claim 失败：提示关闭官方上位机。
- 读超时：可重发 `0x05`；连续失败则重新 `0x01`。
- CRC：主机发送必须正确；设备应答帧未发现同款 55/AA/CRC 封装（读数帧为裸二进制块）。
